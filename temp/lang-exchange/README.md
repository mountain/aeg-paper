# 工程界面上的「自由的信息交换」由什么组织

问题：在 Rust、Python、Ada 的工程界面上，究竟什么组织了自由的信息交换？

场景沿用前一步的数据形状：一组圆 `(x, y, r)`。两个部件 producer / consumer，
边界是函数签名或包规格。观察三件事：

| 轴 | 问题 | Rust | Python | Ada |
|---|---|---|---|---|
| **值** | 什么可以过去 | `struct` + `trait` 约束；按值=移动，`Copy` 才复制 | 任何对象；按引用共享，不声明 | 私有类型 + 子类型 + 参数模式 `in/out/in out`；不同派生类型不隐式转换 |
| **引用** | 谁能持有、能否改 | 所有权唯一；别名 × 可变性互斥（编译期，单调） | 默认共享；`id()` 同一对象；约定与协议，无静态检查 | 可见性（规格/私有部分）；`aliased` + 可访问性层；**不检查别名** |
| **时序** | 什么时候能改 | `Send`/`Sync` 自动判定 + `Mutex`/`channel` 定义临界区 | 解释器的让出点 + `Lock`；GIL 的原子性粒度 | 保护对象（互斥 + 屏障）、任务会合、优先级天花板 |

三者的差别不是"有没有规则"，而是**规则放在哪里检查、代价是什么**。

---

## 一、Rust：把检查放在编译期

合法的交换（`rust/exchange.rs`，`rustc -O` 编译通过并运行）：

```
== (1) 所有权：值能不能自由过去 ==
  按值交出后，consumer 看到 5 个圆；原变量已被移动，此处无法再读写它
  重新造一份后按借用读取：Σr = 2
  可变借用归还后仍可读：Σr = 4
== (2) 内部可变性：把检查从编译期挪到运行期 ==
  两个句柄 h1/h2 指向同一份数据（强引用计数 3）：长度 3
  同时两次 borrow_mut -> 运行期 panic：true
== (3) 跨线程：Send/Sync 由编译器判，临界区由锁定义 ==
  4 线程 × 100 次加锁写入后长度 = 400
== (4) 消息：所有权随消息一起搬过去 ==
  收到一条消息，其中圆的个数 = 3
```

被编译器拒收的四种交换（`rustc --edition 2021`，错误码即证据）：

| 文件 | 尝试做的事 | 编译器结论 |
|---|---|---|
| `reject/reject_move.rs` | 交换之后再用原处 | `E0382: borrow of moved value` |
| `reject/reject_alias.rs` | 同一个值两个 `&mut` | `E0499: cannot borrow as mutable more than once at a time` |
| `reject/reject_send.rs` | 把 `Rc<RefCell<..>>` 送进另一个线程 | `E0277: Rc<RefCell<Vec<u32>>> cannot be sent between threads safely` |
| `reject/reject_lifetime.rs` | 把对局部的引用交出去 | `E0515: cannot return reference to local variable` |

要点：Rust 组织的不是"信息"，而是**别名**。它把交换的自由度收紧到"同一时刻每个值只有一个可写路径"，
于是编译器能静态地保证交换不撕裂。想要别名（`Rc<RefCell<..>>`）就必须把检查挪到运行期——
上面第 (2) 条 `RefCell already borrowed` 的 panic 就是这笔交易的收据。

## 二、Python：规则都在运行期，于是"在哪里让出"成了唯一要紧的事

```
== (1) 值怎么过去：默认共享，不复制 ==
  b is a: True，id 相同: True，引用计数: 2
  通过 b 就地改过之后，a 里第一个圆的半径 = 2.0（a 从未被提到）
== (2) 接口由协议决定，而不是声明 ==
  list -> 4.0 / 生成器 -> 2.0 / 自定义类（只实现 __iter__）-> 1.0
  三者都能过边界：边界不检查类型，只检查运行时有没有 __iter__
== (3) 什么时候能改：由解释器在哪里让出决定，与类型无关 ==
  紧循环 += 1        : 得到   800000 / 应为   800000，丢失        0  (0.04s)
  读改写中夹一次函数调用: 得到   145415 / 应为   800000，丢失   654585  (0.08s)
  读改写中夹一次 sleep(0): 得到   102101 / 应为   800000，丢失   697899  (4.58s)
  同 sleep(0) 但加锁    : 得到   800000 / 应为   800000，丢失        0  (5.49s)
== (4) 哪些操作在 GIL 下恰好是原子的 ==
  4 线程 × 50000 次 append 得到 200000，应为 200000
  GIL 当前是否启用: True
```

这台机器是 CPython 3.14.6（GIL 开启）。最刺眼的一条是第 (3) 组第一行：
8 线程 × 100000 次 `counter[0] += 1`，**一次都没丢**——因为解释器不在读改写三步之间让出；
只要在中间夹一次普通函数调用（一个让出点），80 万次里就丢掉 65 万次。

也就是说：Python 里组织并发交换的不是类型、不是声明，而是
**对象图（谁和谁是同一个对象）+ 解释器的让出点 + 显式锁**。
边界上没有任何静态契约，`is` / 引用计数 / 协议方法就是全部的"界面"。

## 三、Ada：把三条轴拆到两处检查

本机没有 GNAT / alire（Apple clang 不含 Ada 前端），`ada/*.ads|adb` **未经编译验证**，只作结构对照。

| 交换的要素 | Ada 里由什么承载 | 在哪里检查 |
|---|---|---|
| 什么值可以过去 | 私有类型（规格里只见子程序）、子类型约束、流属性 `'Write`/`'Read` | 类型：编译期；约束与表示：运行期（SPARK 可前移） |
| 谁能持有 | 包规格的可见性、`private` 部分、`aliased` + 可访问性层 | 可见性：编译期；可访问性：编译期 + `Program_Error` 兜底 |
| 谁能改 | 参数模式 `in` / `out` / `in out` | 编译期检查模式，**不检查别名**（两个 `in out` 实参可重叠） |
| 什么时候能改 | 保护对象（互斥 + `when` 屏障）、`entry` 会合、`Priority_Ceiling` | 运行期 |

Ada 与 Rust 的对照最清楚：两者都靠静态类型收紧"值"这条轴，但
Rust 进一步收紧"引用"（别名互斥），Ada 把"引用"交给可访问性层、
把"时序"交给语言内建的保护对象与任务——也就是把并发交换的纪律**写进类型系统之外的运行时构件**，
而不是像 Python 那样留给约定。

---

## 结论：组织自由信息交换的是三件东西，语言只是在选检查点

1. **一个值契约**：什么表示可以过界（Rust 的结构体 + trait 约束 / Python 的对象协议 / Ada 的类型+流属性）。
2. **一条引用纪律**：谁可以持有、能否就地改（Rust 所有权 / Python 共享对象图 / Ada 可见性+可访问性）。
3. **一套时序协议**：什么时候允许改（Send+Sync+锁 / 解释器让出点+锁 / 保护对象+任务会合）。

"自由的信息交换"之所以看起来自由，是因为这三件东西里没有被检查的部分默认放开：
- Rust 放开的是运行期别名检查，代价是编译期必须交出唯一所有权；
- Python 放开的是静态检查，代价是并发正确性由让出点和锁决定；
- Ada 放开的是别名检查（`in out` 可重叠），代价是要显式写出保护对象与任务结构。

一句话：**界面上真正传递的不是"信息"，而是"边界两边都认可的一个不变量"；语言的区别在于
这个不变量在哪里被检查，以及为了让它可检查，你放弃了哪一种自由。**

（与 AEG 侧的联系仅作类比登记，不作为数学断言：一个界面就是一条"换图规则"，
组织自由交换的是跨界保持不变的那个结构；先前几轮里保持下来的是共形结构与奇点切锥，
这里保持下来的是表示、引用纪律与时序协议。）
